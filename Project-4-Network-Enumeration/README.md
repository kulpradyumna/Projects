# Project 4: Network Enumeration & Active Exploitation

## Objective
To execute a simulated cyberattack involving network reconnaissance, web directory enumeration, and password brute-forcing, followed by defensive log analysis to identify the attacker's footprint.

## Skills & Tools Demonstrated
* **Red Team Tools:** Nmap, Dirb, Hydra
* **Blue Team Tools:** Linux CLI, `grep`, Apache Access Logs, Syslog (`auth.log`)
* **Core Concepts:** Vulnerability Scanning, Dictionary Attacks, Incident Response, Log Analysis

## Phase 1: The Attack (Red Team)
Operating from the `Attacker-VM`, I utilized open-source penetration testing tools to map the target and exploit weak credentials.

1. **Network Scanning (Nmap):** Executed an aggressive Nmap scan (`nmap -A`) against the target IP. Discovered open ports and identified specific service versions, noting the presence of OpenSSH 8.9p1.
2. **Directory Enumeration (Dirb):** Launched a Dirb scan against the target's web server to brute-force and uncover hidden directories.
3. **Active Exploitation (Hydra):** Conducted a dictionary attack against the SSH service using Hydra. By feeding it a common password list, the tool successfully brute-forced the credentials and cracked the SSH password.



## Phase 2: Incident Response (Blue Team)
After successfully compromising the target, I pivoted to the `Honeypot-VM` to act as the defender, reviewing the system logs to identify exactly what the attacks looked like from the server's perspective.

1. **Web Server Log Analysis:** Queried the Apache access logs (`cat /var/log/apache2/access.log | grep dirb`). I successfully identified the massive flood of web requests generated by Dirb and noted the automated tool's default, fake "Windows NT" User-Agent.
2. **Authentication Log Analysis:** Queried the Linux system authentication logs (`cat /var/log/auth.log | grep sshd`). The logs revealed a massive spike in failed password attempts, clearly indicating the Hydra brute-force attack.
